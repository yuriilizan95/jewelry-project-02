🟢 Початок роботи та оновлення Ці команди допоможуть тримати локальний код у
актуальному стані.

git pull origin main — завантажити останні зміни з головної гілки репозиторію та
об'єднати їх зі своїм кодом.

git fetch — перевірити наявність оновлень на сервері (нових гілок або комітів),
не змінюючи твій локальний код.

git clone [URL] — клонувати проєкт на свій комп'ютер (використовується лише один
раз на початку).

🟡 Робота з гілками (Branching) Головне правило: кожна нова функція або
виправлення помилки — це окрема гілка.

git checkout -b feature/назва-завдання — створити нову гілку та одразу перейти
на неї.

git checkout назва-гілки — переключитися на вже існуючу гілку.

git branch — переглянути список усіх локальних гілок.

git merge main — перебуваючи у своїй гілці, ввібрати в неї зміни з головної
гілки (щоб уникнути конфліктів пізніше).

🟠 Збереження змін Процес фіксації твоєї роботи.

git status — перевірити стан файлів: які змінено, які додано, а які ще не
відстежуються Git.

git add . — додати всі змінені файли до списку на збереження (підготувати до
коміту).

git commit -m "feat: опис змін" — створити "злімок" змін із коротким описом
того, що було зроблено.

🔵 Відправка коду (Sharing) Як поділитися результатом з командою.

git push origin назва-твоєї-гілки — відправити свою гілку на GitHub, щоб інші
могли її побачити або зробити Pull Request.

🔴 Виправлення помилок та скасування Якщо щось пішло не так (як у випадку з
ENOENT через відсутні файли).

git restore . — скасувати всі незакріплені зміни у файлах і повернути їх до
стану останнього коміту.

git checkout package.json — відновити конкретний файл, якщо він був випадково
видалений або змінений (як ми робили раніше).

git clean -fd — видалити всі нові файли та папки, які не відстежуються Git
(обережно, це видалить їх назовсім).
